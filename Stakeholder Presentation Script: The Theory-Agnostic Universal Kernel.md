# Stakeholder Presentation Script: The Theory-Agnostic Universal Kernel

## Intended length: 9–11 minutes

### 1. Opening — What changed

“Today’s decision is a correction, not a cosmetic rename. Sovereign Engine is not a Geometric Unity engine, and it is not an engine for any other single theory. It is a theory-agnostic verification kernel. Its job is much narrower and more useful: take a declared claim, an explicit structure, and a named check; then return evidence about that one check.”

### 2. Why the correction matters

“Research frameworks can each contain useful ideas, incomplete models, incompatible assumptions, or different levels of evidence. If the kernel silently privileges one framework, it can turn a local computational result into an implied worldview. That is exactly what we are preventing. A successful receipt is evidence about a stated predicate, not proof that a framework—or reality-level interpretation—is correct.”

### 3. The input model

“An adapter packet names the framework only for provenance. It also names the individual claim, the claim class, the check, and the declared input. The key design decision is that `framework_id` never selects mathematical behavior. It is a label for traceability, not a secret branch in the evaluator.”

### 4. Comparative demonstration

“We ran the same symmetric-matrix claim under seven labels: Geometric Unity, causal set, exceptional algebra, amplitudes/twistor, noncommutative geometry, holographic QEC, and custom research. All seven returned `verified` with the exact same receipt ID. That does not say those frameworks are equivalent. It says the adapter treats identical structural input identically.”

### 5. What the kernel can evaluate

“Today’s public portfolio is intentionally small: matrix symmetry, identity, a declared inverse, and a finite partial order. The partial-order check is important because it is useful across many domains: a precedence graph, a dependency relation, a causal-order candidate, or any finite ordering proposal. It checks only reflexivity, antisymmetry, and transitivity.”

### 6. What it will not pretend to know

“Empirical, interpretive, and metaphysical claims are not forced into a fake score. They return `unverifiable` in the deterministic kernel because they need a different evidence process: data provenance, uncertainty models, experimental protocols, arguments, or philosophical reasoning. ‘Unverifiable here’ is an honest boundary, not a dismissal.”

### 7. Assurance remains optional

“Ordinary users see a plain receipt. Advanced users can replay the result, inspect a local audit attachment, review a local Merkle inclusion proof, or inspect an offline Ed25519 fixture outcome. These are assurance layers. They improve inspectability, but they do not turn the current offline release into a production consensus system or public transparency service.”

### 8. Roadmap

“The next build waves add new bounded adapters: a graph invariant, a finite tensor predicate, a data-to-claim descriptor, and eventually formal bridges. Each must pass the same admission gate: explicit object, predicate, assumptions, fixtures, receipt scope, replay, audit, and non-claims. That is how we let multiple theories contribute useful structures without allowing any one of them to capture the kernel.”

### 9. Closing

“The principle is simple: **compare claims fairly; verify structures precisely; preserve uncertainty honestly.** Sovereign Engine is the common evidence layer below theories, not the theory above them.”
