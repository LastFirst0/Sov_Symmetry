# Third-Party Adapter Admission Test Policy v0.1

An adapter may enter the offline universal kernel only after every required fixture category passes, the same declared input produces the same receipt across provenance labels, replay survives clean process restart, a one-field mutation produces an explained change or `unverifiable`, and the release report records the adapter version and fixture hash. Passing these tests establishes only deterministic behavior within the stated scope.

The test oracle must be derived from the written predicate specification and frozen fixture declarations—not from the implementation under test. A failure in the implementation, fixture pack, scope statement, or neutrality rule blocks admission until the discrepancy is explicitly resolved and versioned.
