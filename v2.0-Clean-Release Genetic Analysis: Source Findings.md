# v2.0-Clean-Release Genetic Analysis: Source Findings

**Inspection target:** `LastFirst0/Sovereign_Engine`, branch `v2.0-clean-release`, commit `a3e473e` (`feat(genomics): add UniversalGenomicManifold for multi-species longevity mining`).  
**Purpose:** Record observed code behavior before deciding whether molecular sequence data should replace lexical hierarchy as the first geometry-representation experiment domain.

## Observed implementation evidence

| Surface | Observed behavior | What it supports | What it does not support |
|---|---|---|---|
| `UniversalGenomicManifold` | Registers **9 manually curated species profiles** with lifespan and biological-score fields; computes an 8D input by SHA-256 hashing a concatenated species name, labels, scalar scores, and short gene strings; normalizes then E8-snaps it. [1] | A deterministic software pipeline over its provided records. | Comparative genomics, orthology inference, sequence alignment, biological causal discovery, or validated longevity intervention recommendations. |
| “Genomic” inputs | The profile stores a handful of short literal strings per named gene, rather than retrieved genome assemblies, transcript records, sequence provenance, alignments, or annotations. [1] | A small hand-authored demonstration dataset. | DNA/RNA/genome-scale modeling or an auditable link to the stated NCBI assemblies. |
| E8 / CRT / Poincaré fields | E8 roots are assigned after the hash-derived projection; CRT coordinates hash the species name; Poincaré depth is a generic transform of the same 8D vector. [1] [4] | Repeatable geometry applied to the created vectors. | Evidence that the coordinates reflect molecular structure, evolutionary distance, phenotype, or mechanism. |
| Adaptation index | A fixed weighted sum of three prefilled 0–1 scores ranks the nine profiles. [1] | Deterministic ranking of the supplied scalar values. | An empirically calibrated longevity or disease-risk model. |
| Report recommendations | The report lists five “human application” recommendations, but there is no dataset ingestion, model training, validation protocol, uncertainty estimation, or independent biological evaluation in the code. [1] [2] | The presence of aspirational recommendation text. | Medical, clinical, or translational claims. |
| Codon mapper | Maps standard codons to amino-acid names, then assigns E8 root/Sedenion/Sefirot/Merkaba fields by SHA-256 modulo operations. [3] | Deterministic symbolic lookup over the genetic code. | Biophysical codon meaning, RNA translation dynamics, protein structure, or a scientific E8 encoding. |
| Protein node | Maps amino-acid names to 8D bridge coordinates, uses hydrophobicity weights and internal centroid/swarm logic, and outputs an 8D coordinate plus a heuristic “misfolding” label. [5] | A running sequence-to-internal-geometry workflow. | Atomistic folding, energy minimization, residue contact prediction, PDB agreement, or biochemical misfolding prediction. |
| Tests | Genomic tests check registry population, output shape/range, custom registration, and the manually encoded adaptation score; they do not test against external genomic, protein, or phenotype labels. [6] | API and deterministic-shape regression. | Biological correctness or predictive utility. |

## External evidence relevant to a future molecular pilot

The choice of molecular sequences **is reasonable as a research domain**, but only if the experiment uses public biological data, a realistic task, independently measured labels, and matched baselines. Open English WordNet was a good first proof that the research machinery can preserve a negative result. Molecular sequences offer clearer objective labels and existing geometry-aware baselines, but their scientific stakes are higher.

The ICLR 2025 paper *Hyperbolic Genome Embeddings* reports a specific hyperbolic CNN framework evaluated against Euclidean alternatives across genome-interpretation benchmarks; it is evidence that a hyperbolic **genome-representation hypothesis can be empirically tested**, not evidence that any arbitrary E8 or hash-derived DNA mapping is biologically meaningful. [7]

ProteinWorkshop describes benchmarked protein-structure representation learning with declared datasets, tasks, splits, and metrics. Its setup illustrates the minimum bar for a protein-geometry study: validated labels and controls rather than an internally generated “fold” coordinate. The PMC page labels the reviewed manuscript as a preprint, so it should be treated as a useful benchmark design reference rather than a final authority. [8]

DNABERT-2 introduced the Genome Understanding Evaluation (GUE), a multi-species DNA classification benchmark described as containing 36 datasets across nine tasks with input lengths from 70 to 10,000 nucleotides. GUE is a more appropriate initial source than the branch’s manually curated species table because it gives a task-and-split discipline against which Euclidean and hyperbolic candidates can be compared. [9]

The HGE reference repository exposes model/configuration code and points to its Transposable Elements Benchmark download, but it is a small supplementary-code repository with no release package. It is useful as a comparative reproduction target, not as a trusted dependency or a substitute for pinning data, environment, and evaluator behavior. [10]

## Immediate conclusion

> The branch contains **symbolic and synthetic molecular-mapping prototypes**, not validated models of DNA, RNA, amino acids, proteins, tissues, genomes, or disease. It should not be connected to medical use, translational recommendation, or a trusted biological adapter in its present form.

Molecular sequences are a promising next research domain **only after a clean replacement of the data and evaluation layer**. The appropriate first experiment is a small, public, non-clinical sequence benchmark—such as protein-family classification or a bounded DNA regulatory-element label task—with raw sequence provenance, train/test split discipline, Euclidean/random/matched-hyperbolic controls, and negative results retained. The legacy codon, E8, CRT, and protein-node modules can contribute candidate transforms only after they are re-expressed as exact algorithms whose benefit is tested against those controls.
